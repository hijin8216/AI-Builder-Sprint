# AI Builder Sprint 2026

> 총 168시간, AI와 함께 만드는 도전

## 대회 소개

**AI Builder Sprint 2026**은 부산대학교 **APPTIVE**가 주최하고, **Upstage**, 부산대학교 **Anchor 사업단** 및 부산대학교 **AI융합교육원**이 후원하는 해커톤입니다. 참가자들은 자유로운 기술 스택을 바탕으로 실제로 동작하는 서비스를 직접 코드로 구현합니다.

| 항목 | 내용 |
| --- | --- |
| 주제 | AI를 통해 인간다움을 더욱 잘 드러낼 수 있는 서비스 개발 |
| 팀 구성 | 2~4인 1팀 |
| 개발 방식 | 코드 기반 앱 개발 필수 (노코드/로우코드 단독 사용 불가) |

### 진행 흐름

1. **팀 단위 참가 신청** — 팀원 정보, 프로젝트 아이디어, 활용 예정 AI 기술·API 제출
2. **참가팀 선발** (20~50팀) — 아이디어 참신성·실현 가능성·AI 활용 계획 기반 서류 심사
3. **예선 개발 기간** (7.27 ~ 8.3, 약 1주일) — API 크레딧 발급, 아이디어 구체화 및 개발
4. **결과물 제출 및 1차 심사** — 데모 영상/배포 링크, 코드 저장소, 발표 자료, AI 활용 증빙 제출
5. **본선 발표 및 질의응답** (8.7) — 팀당 7분 발표 + 5분 Q&A, 심사 후 수상팀 확정

### 기술 스택 및 규칙

- 사용 API·모델은 자유이며, **Upstage API**(Solar LLM, Document Parse, Information Extract) 활용 시 심사 가점
- Claude, GPT, Gemini 등 타사 모델 병행 사용 가능 (제약 없음)
- 프레임워크/언어 자유 (Python, JavaScript, React, Flutter 등)
- 결과물은 데모 가능한 동작하는 앱 (웹앱, 모바일앱, CLI 도구 등 형태 무관)
- 코딩 에이전트(Claude Code, Codex 등) 활용 시 `.claude/`, `AGENTS.md` 등 관련 설정·지침 파일을 저장소에 포함해야 심사에 반영됩니다

## WAVEON BUSAN 데모 실행

이 저장소에는 부산 해양레저 검색·예약 및 Solar 맞춤 추천 데모가 포함되어 있습니다.

### 처음 한 번만 준비하기

1. [Node.js](https://nodejs.org/)를 설치합니다.
2. 프로젝트 폴더에서 `npm install`을 실행합니다.
3. `.env.example`을 참고해 `.env` 파일을 만들고 API 키를 입력합니다.

```env
UPSTAGE_API_KEY=발급받은_키
MODUSIGN_EMAIL=모두싸인_워크스페이스_이메일
MODUSIGN_API_KEY=모두싸인_API_키
MODUSIGN_TEMPLATE_ID=판매자_계약서_템플릿_ID
PORT=3000
```

`.env` 파일은 `.gitignore`에 포함되어 있으므로 GitHub에 올리지 않습니다.

기존 상품의 전자서명 계약서 ID는 `data/contract-templates.json`에 저장하고, 상품별 계약서 선택은 `data/products.json`의 `contractTemplateKeys`에서 관리합니다. 판매자가 새로 등록한 상품에 공통으로 사용할 계약서는 `.env`의 `MODUSIGN_TEMPLATE_ID`에 입력합니다. 사진·영상 활용 동의서와 미성년자 법정대리인 동의서는 선택 동의가 필요한 항목이므로 기본 계약서 묶음에는 넣지 않았습니다.

### 실행하기

프로젝트 폴더에서 다음 명령어를 실행합니다.

```bash
npm start
```

웹 브라우저에서 `http://127.0.0.1:3000`에 접속합니다.

1. 오른쪽 위 **로그인**에서 이메일, 아이디, 비밀번호로 회원가입합니다.
2. 이후에는 아이디와 비밀번호만으로 로그인합니다.
3. **AI 맞춤 추천**을 눌러 예산과 취향을 입력합니다.
4. Solar가 추천한 상품 3개와 추천 이유를 확인합니다.
5. 상품 카드를 눌러 예약과 전자서명 흐름을 체험합니다.
6. 웹사이트 안의 모두싸인 화면에서 서명하면 완료 문서가 회원가입 이메일로 전달됩니다.
7. **마이페이지**에서 내 예약 상태와 완료된 전자서명 문서를 다시 확인합니다.
8. 상단의 **파트너 입점**을 누르면 판매자 센터(`/seller`)로 이동합니다.
9. 판매자 계정이 없으면 **판매자 등록**에서 계정과 사업자 정보를 입력합니다. 기존 구매자 계정도 같은 이메일·아이디·비밀번호로 판매자 계정으로 전환할 수 있습니다.
10. 판매자로 로그인한 뒤 **새 상품 작성**을 누르면 별도 화면에서 기본 정보, 사진·체험, 운영 정보, 약관·안전 순서로 상품을 등록할 수 있습니다.
11. 판매자 센터의 **내 판매 상품** 카드를 누르면 같은 화면에서 기존 상품 정보와 사진을 수정할 수 있습니다.
12. 구매자가 판매자의 상품을 예약하면 판매자 센터의 **들어온 예약**에 고객 정보가 자동으로 표시되며, 별도 입력 없이 모두싸인 계약서를 발송할 수 있습니다.

일반 회원은 판매자 센터와 판매자용 API를 사용할 수 없습니다. 판매자 등록을 완료한 계정과 기존에 판매 상품을 등록한 계정만 판매자 권한을 가집니다.

Solar API 호출에 실패하더라도 상품 점수 계산을 이용한 기본 추천이 표시됩니다.

데모 계정은 `data/users.local.json`에 비밀번호 해시로 저장되고, 예약과 전자서명 문서
연결 정보는 `data/reservations.local.json`에 저장됩니다. 두 파일 모두 Git에는 올라가지
않습니다. 서버를 다시 시작하면 보안을 위해 기존 로그인 세션은 종료되므로 다시 로그인해야
합니다.

판매자가 등록한 상품과 계약 발송 기록도 `data/seller-posts.local.json`,
`data/seller-contracts.local.json`에 계정별로 저장되며 Git에는 올라가지 않습니다.
판매자가 올린 상품 사진은 `data/seller-uploads.local/`에 저장되며 이 폴더도 Git에는
올라가지 않습니다.
실제 계약서 이메일 발송에는 `.env`의 모두싸인 이메일, API 키, 템플릿 ID와 API 사용량이
필요합니다.

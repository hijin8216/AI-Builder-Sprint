# AI 사용 기록

## 추천 기능

- 사용 모델: Upstage Solar Pro 3 (`solar-pro3`)
- API 호출 파일: `server.js`
- API 주소: `https://api.upstage.ai/v1/chat/completions`
- 비밀값 관리: `UPSTAGE_API_KEY`를 `.env`에 저장하며 GitHub에는 올리지 않는다.

### 처리 과정

1. 사용자가 예산, 나이, 지역, 선호 활동, 경험 수준, 수영 가능 여부, 동행 유형과 원하는 분위기를 입력한다.
2. `server.js`가 `data/products.json`에서 안전·예산·난이도 조건을 만족하는 상품을 거른다.
3. 코드로 상품별 추천 점수를 계산해 상위 5개 후보를 선정한다.
4. 후보 상품과 사용자 조건만 Solar Pro 3에 전달한다.
5. Solar는 상위 3개 상품의 추천 이유, 적합한 점과 안전 주의사항을 JSON으로 반환한다.
6. Solar 호출에 실패하면 코드로 계산한 추천 결과를 대신 표시한다.

### 주요 프롬프트 규칙

- 제공된 후보 상품 정보만 사용한다.
- 확인할 수 없는 사실을 만들지 않는다.
- 안전 주의사항을 숨기지 않는다.
- 상품 ID, 추천 이유, 적합한 점, 주의사항을 JSON 형식으로 반환한다.

### 설정

- 추천 설명 생성 온도: `0.2`
- Solar 연결 제한 시간: 15초
- Solar에 전달하는 후보 상품: 최대 5개
- 사용자에게 표시하는 추천 상품: 최대 3개

## 상품 상세페이지 약관 요약

- 사용 모델: Upstage Solar Pro 3 (`solar-pro3`)
- API 호출 파일: `server.js`
- 호출 경로: `POST /api/contract-summary`
- 입력 데이터: 상품별 환불 규정, 예약 조건, 추가 약관, 안전 조건
- 출력 항목: `환불 주의사항`, `나에게 불리할 수 있어요`
- 주의도: `매우높음`, `높음`, `보통`, `낮음`, `매우낮음`
- 생성 온도: `0.1`
- 연결 제한 시간: 60초

`EN`, `JP`, `中文` 화면에서는 같은 경로에 각각 `locale: "en"`, `locale: "ja"`, `locale: "zh"`를 전달해 Solar가 선택한 언어의 요약을 반환하도록 한다. 주의도 자체는 같은 기준을 사용하고 화면 언어에 맞게 표시한다.

Solar가 연결되지 않거나 응답 형식이 올바르지 않으면, 같은 약관 원문을 규칙 기반으로 분석한 결과를 대신 표시한다. AI 요약은 원문을 대체하지 않으며 상세페이지 아래쪽에서 전체 약관을 함께 확인할 수 있다.

## 판매자 계약 템플릿 추천

- 사용 모델: Upstage Solar Pro 3 (`solar-pro3`)
- API 호출 파일: `server.js`
- 호출 경로: `POST /api/seller/contract-recommendations`
- 입력 데이터: 판매 상품의 카테고리, 설명, 난이도, 활동 강도, 수영 필요 여부, 참여 연령, 날씨 영향, 포함 장비, 환불 정책, 참가 조건과 안전 주의사항 및 해당 예약자의 미성년 여부
- 추천 대상: `data/contract-templates.json`에 등록된 템플릿 key만 사용
- 생성 온도: `0`
- 연결 제한 시간: 15초

서버 규칙이 예약 및 이용약관, 개인정보 동의, 기본 해양 안전과 환불 규정을 필수 항목으로 먼저 지정한다. 선박, 장비, 잠수, 촬영과 날씨 관련 계약서는 상품 데이터에 따라 추가한다. 미성년자 법정대리인 동의서는 상품의 최소 연령이 아니라 구매자가 해당 예약에서 선택한 `isMinor` 값이 `true`일 때만 필수 추천한다. Solar는 이 선택을 뒤집을 수 없으며, 규칙상 필수인 항목을 해제하거나 새로운 계약 조항을 만들 수 없다.

판매자가 최종 체크한 템플릿만 모두싸인 초안 생성에 사용한다. Solar 호출에 실패하거나 키가 없으면 같은 규칙 기반 추천을 표시한다. 추천 결과는 상품 ID, 수정 시점과 예약자의 미성년 상태를 기준으로 24시간 캐시해 같은 조건에서 반복 호출하지 않는다.

## 상품 상세 다국어 번역

- 사용 모델: Upstage Solar Pro 3 (`solar-pro3`)
- API 호출 파일: `server.js`
- 호출 경로: `POST /api/product-translation`
- 실행 시점: 사용자가 `EN`, `JP`, `中文` 중 한 언어를 선택한 뒤 상품 상세페이지를 열 때
- 입력 데이터: 상품명, 판매자명, 장소, 포함 사항, 상품 소개, 환불 규정, 예약 조건, 추가 약관, 안전 조건
- 출력 데이터: 기존 JSON 구조를 유지한 선택 언어의 상품 상세와 예약 전 세부 조건
- 생성 온도: `0`
- 연결 제한 시간: 60초

번역 결과는 서버 메모리와 현재 브라우저 페이지의 `언어 + 상품` 캐시에 저장해 같은 언어의 상품을 다시 열 때 Solar를 반복 호출하지 않는다. 번역을 준비하지 못하면 사용자는 한국어 원문을 계속 확인할 수 있다.

다국어 화면으로 전환할 때는 `POST /api/product-card-translations`가 현재 목록에 보이는 최대 8개 카드의 상품명과 판매자명만 번역해 적용한다. 전체 상품을 한꺼번에 번역하지 않으며, 상세 내용과 약관은 사용자가 상품을 열었을 때 별도로 번역한다.

다국어 상세 화면은 상세 번역이 준비되는 동안 상단에 진행 안내를 표시한다. 본문은 계속 보이며, Solar 응답이 도착하면 선택한 언어의 상세와 약관으로 교체한다.

다국어 약관 요약은 선택 언어 전용 프롬프트를 사용한다. Solar를 사용할 수 없으면, 이미 번역된 상세 약관을 우선 사용한 해당 언어의 대체 요약을 표시한다.

클라이언트에서 요약 요청 자체가 실패해도 다시 시도 문구만 표시하지 않고, 현재 상세 약관에서 만든 화면용 요약을 즉시 표시한다.

## 화면 문구 다국어 번역

- 사용 모델: Upstage Solar Pro 3 (`solar-pro3`)
- API 호출 파일: `server.js`
- 호출 경로: `POST /api/interface-translations`
- 실행 시점: 사용자가 `JP` 또는 `中文`을 처음 선택할 때
- 입력 데이터: 사이트의 고정 화면 문구
- 출력 데이터: HTML 태그와 숫자를 유지한 일본어 또는 중국어 화면 문구
- 생성 온도: `0`
- 연결 제한 시간: 60초

일본어와 중국어의 주요 고정 화면 문구는 코드에 포함되어 있어 AI 호출 없이 즉시 표시한다. 나머지 고정 문구는 첫 전환 시 24개씩 번역한 뒤 서버 메모리와 현재 브라우저 페이지에 저장한다. 영어 고정 문구는 코드에 포함되어 있어 AI 호출 없이 즉시 표시한다.

## 실제 모두싸인 계약서 PDF 점검

- 문서 추출 모델: Upstage Document Parse (`document-parse`)
- 약관 요약 모델: Upstage Solar Pro 3 (`solar-pro3`)
- API 호출 파일: `server.js`
- 호출 경로: `POST /api/signature/contract-summary`
- 실행 시점: 모두싸인 계약 문서가 생성된 뒤 구매자가 웹사이트의 서명 화면을 열 때

### 처리 과정

1. 로그인한 구매자의 예약과 모두싸인 문서 ID가 일치하는지 확인한다.
2. 모두싸인 API에서 실제 서명 대상 PDF 다운로드 주소를 가져온다.
3. PDF를 내려받아 Upstage Document Parse의 강제 OCR과 HTML 출력으로 문서 내용을 읽는다.
4. Solar에 보내기 전에 예약자 이름, 이메일, 전화번호와 식별번호 형식의 개인정보를 마스킹한다.
5. Solar가 실제 문서에서 취소·환불 제한과 소비자에게 불리할 수 있는 조항만 JSON으로 정리한다.
6. 분석 결과를 문서 ID와 언어별로 캐시하고 예약 데이터에도 저장해 같은 문서를 반복 호출하지 않는다.
7. 구매자는 AI 요약 옆의 모두싸인 임베디드 화면에서 원문을 직접 확인하고 서명한다.

### 안전 원칙

- AI 요약은 계약서 원문을 대체하지 않는다.
- 계약서에 없는 사실이나 법률 판단을 새로 만들지 않는다.
- 위험도는 상품 데이터의 기준값을 유지한다.
- 알려진 개인정보는 외부 LLM 호출 전에 가린다.
- PDF가 없거나 Upstage 호출에 실패하면 실제 문서를 분석했다고 표시하지 않고 오류를 안내한다.

## API 장애 시 대체 동작

| 기능 | 정상 연결 | API를 사용할 수 없을 때 |
| --- | --- | --- |
| 맞춤 추천 | Solar가 추천 이유·적합점·주의사항 작성 | 코드가 계산한 점수 기반 추천 표시 |
| 상품 약관 요약 | Solar가 환불·불리 조항 요약 | 저장된 약관을 규칙 기반으로 요약 |
| 상품 번역 | Solar가 선택 언어로 번역 | 한국어 원문 또는 내장 번역 유지 |
| 실제 계약서 PDF 분석 | Document Parse와 Solar로 실제 문서 분석 | 분석 실패를 알리고 계약서 원문 확인 유도 |

실제 전자서명 문서 분석은 원본 PDF가 있어야 하므로 임의의 로컬 요약을 실제 문서 분석 결과처럼 표시하지 않는다.

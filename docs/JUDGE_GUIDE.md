# WAVEON BUSAN 심사위원 실행 가이드

이 문서는 처음 프로젝트를 받은 환경에서 웹사이트를 실행하고 핵심 기능을 확인하는 순서를 설명합니다.

## 1. 프로젝트 한눈에 보기

WAVEON BUSAN은 부산 해양레저 상품을 사용자 조건에 맞게 추천하고, 예약 약관에서 환불 제한과 불리할 수 있는 조항을 AI로 점검한 뒤 모두싸인 전자서명까지 연결하는 웹서비스입니다.

- 구매자 화면: `http://127.0.0.1:3000`
- 판매자 화면: `http://127.0.0.1:3000/seller`
- 서버 상태 확인: `http://127.0.0.1:3000/api/health`
- 사용 기술: Node.js, Express, HTML, CSS, JavaScript
- 외부 API: Upstage Solar Pro 3, Upstage Document Parse, 모두싸인 API

## 2. 준비물

- Node.js 20 이상 권장
- npm
- 의존성 설치를 위한 인터넷 연결
- 전체 AI·전자서명 시연 시 Upstage 및 모두싸인 인증 정보

API 키가 없어도 상품 탐색, 필터, 회원가입, 기본 추천, 판매 상품 등록 화면은 실행할 수 있습니다. 다만 Solar 응답 대신 로컬 추천·요약이 표시되고, 실제 전자서명과 실제 계약서 PDF 분석은 진행할 수 없습니다.

## 3. 설치

저장소를 내려받은 다음 프로젝트 폴더로 이동합니다.

```bash
git clone <제출된-GitHub-저장소-주소>
cd AI-Builder-Sprint
npm install
```

Windows PowerShell에서 `npm` 실행 정책 오류가 나오면 다음처럼 `.cmd` 명령을 사용합니다.

```powershell
npm.cmd install
```

## 4. 환경변수 설정

프로젝트 루트의 `.env.example`을 복사해 `.env`를 만듭니다.

Windows PowerShell:

```powershell
Copy-Item .env.example .env
```

macOS 또는 Linux:

```bash
cp .env.example .env
```

`.env`에 아래 값을 입력합니다. 비밀값은 GitHub에 올리지 않습니다.

```env
UPSTAGE_API_KEY=발급받은_Upstage_API_키
MODUSIGN_EMAIL=모두싸인_워크스페이스_이메일
MODUSIGN_API_KEY=모두싸인_API_키
MODUSIGN_SIGNER_ROLE=
PORT=3000
```

`MODUSIGN_SIGNER_ROLE`은 서버가 템플릿의 서명자 역할을 자동으로 찾지 못할 때만 입력합니다. 모두싸인 전자서명에는 `data/contract-templates.json`에 등록된 템플릿에 접근할 수 있는 워크스페이스 계정이 필요합니다.

## 5. 실행과 종료

macOS 또는 Linux:

```bash
npm start
```

Windows PowerShell:

```powershell
npm.cmd start
```

다음 문구가 나오면 실행된 것입니다.

```text
WAVEON BUSAN server: http://127.0.0.1:3000
```

브라우저에서 `http://127.0.0.1:3000`을 엽니다. 서버를 종료할 때는 터미널에서 `Ctrl+C`를 누릅니다.

## 6. API 키 없이 확인하는 5분 시나리오

1. 구매자 첫 화면에서 지역·종목 필터와 정렬을 확인합니다.
2. `AI 맞춤 추천`을 누르고 예산, 나이, 지역, 경험 수준 등을 입력합니다.
3. 로컬 점수 기반 추천 상품 3개와 추천 이유를 확인합니다.
4. 상품 사진을 눌러 상세 소개, 전체 약관, 글자 크기 조절과 약관 읽기 기능을 확인합니다.
5. `AI 약관 요약`을 눌러 로컬 대체 요약이 정상 표시되는지 확인합니다.
6. 오른쪽 위 언어 선택에서 한국어, 영어, 일본어, 중국어 화면을 확인합니다.
7. 회원가입 후 예약 요청과 마이페이지 예약 목록을 확인합니다.

전자서명 버튼은 실제 모두싸인 인증 정보가 없으면 오류 안내가 표시되는 것이 정상입니다.

## 7. 전체 AI·전자서명 시나리오

이 시나리오는 유효한 Upstage 및 모두싸인 설정이 필요하며 API 사용량이 발생합니다.

1. 구매자 화면에서 새 계정을 만듭니다. 전자서명 완료 문서를 받을 수 있는 이메일을 사용합니다.
2. `AI 맞춤 추천`을 실행해 응답 모드가 Solar인지 확인합니다.
3. 기본 상품을 예약하고 상단 종 모양 알림을 누릅니다.
4. 알림 숫자가 1 감소하고 계약 확인 화면이 열리는지 확인합니다.
5. 주요 약관에 동의하고 모두싸인 보안 서명 화면을 엽니다.
6. 실제 모두싸인 PDF를 Upstage Document Parse가 읽고, Solar가 환불·불리 조항을 요약하는지 확인합니다.
7. 서명을 완료한 뒤 마이페이지에서 `예약 확정` 상태와 완료 문서를 확인합니다.

## 8. 구매자·판매자 연결 시나리오

구매자와 판매자 로그인을 동시에 유지하려면 일반 창과 시크릿 창처럼 서로 다른 브라우저 세션을 사용하면 편리합니다.

1. `/seller`에서 판매자 계정을 등록합니다.
2. 판매자 센터에서 새 상품을 작성하고 게시합니다.
3. 다른 브라우저 세션의 구매자 화면에서 방금 등록한 상품을 예약합니다.
4. 판매자 센터 `들어온 예약`에서 계약서를 발송합니다.
5. 구매자 화면의 종 모양 알림을 눌러 계약서 확인과 전자서명을 진행합니다.
6. 판매자 센터에서 계약 상태를 새로고침해 서명 완료 여부를 확인합니다.

## 9. 로컬 데이터와 초기화

실행 중 생성되는 계정, 예약, 판매 상품과 업로드 이미지는 `data/*.local.json` 및 `data/seller-uploads.local/`에 저장됩니다. 이 파일들은 `.gitignore`에 포함되어 GitHub에 올라가지 않습니다.

서버를 재시작하면 로그인 세션은 초기화되지만 저장된 계정과 예약은 유지됩니다. 심사 환경을 초기화하려면 서버를 종료한 뒤 로컬 데이터 파일을 별도로 백업하고 정리해야 합니다.

## 10. 문제 해결

- `npm.ps1을 로드할 수 없습니다`: `npm.cmd install`, `npm.cmd start`를 사용합니다.
- `EADDRINUSE`: 3000번 포트를 사용하는 프로그램을 종료하거나 `.env`의 `PORT`를 다른 번호로 변경합니다.
- Solar 대신 로컬 결과가 표시됨: `.env`의 `UPSTAGE_API_KEY`와 인터넷 연결을 확인합니다.
- 모두싸인 403 오류: API 사용량, 워크스페이스 권한, 템플릿 접근 권한을 확인합니다.
- 서명자 역할 오류: 모두싸인 템플릿의 역할 이름을 `MODUSIGN_SIGNER_ROLE`에 입력합니다.
- 기존 로그인이 풀림: 서버 재시작 시 메모리 세션이 초기화되므로 다시 로그인합니다.
